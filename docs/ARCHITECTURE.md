# Marathon Agent: system architecture

Updated Oct 11, 2026, after the architecture fixes the athlete approved (items 1–6). Lists what each
part does, how data flows, the decisions behind the design, and what is still open.

## 1. The big picture

```
                          ┌──────────────────────────────┐

                          │ chat, photos, MFP screenshots│

                          └──────────────┬───────────────┘
                                         │
```

## 2. Components

| File | Role |
|---|---|
| `CLAUDE.md` | **The only rulebook**: coach rules, hard gates, consult cases, scheduling, headless rules, routine. |
| `brain_knowledge_base.md` | The athlete: profile, goals, injuries, gear, the athlete's Rules 1–12. No process rules. |
| `brain_current_week_plan.py` | This week's plan and completed sessions. |
| `brain_long_term_roadmap.md` | Fitness-triggered phases toward "faster and longer". |
| `brain_athlete_history.md` | Generated by the tracker: milestone ledger, paces, trends, plateaus. |
| `brain_progress_state.json` | Plateau state between tracker runs. |
| `brain_session_notes.md` | Handoff between sessions. |
| `brain_decision_log.md` | Consults and overrides with outcomes (learns whether the athlete's feel or HRV predicts better). |
| `brain_strength_records.md`, `brain_nutrition_log.md` | Manual logs (best sets; macros from screenshots). |
| `knowledge_base/PRINCIPLES.md` | Research digest: 32 cited principles with evidence grades. |
| `knowledge_base/RESEARCH_LOG.md` | Every lookup with sources. |
| `knowledge_base/*` (other) | Full library summaries, read at block planning. |
| `archive/` | Retired files: old marathon plan, Jan 2026 operating manual, mid-year 2026 report. |

## 3. The loops

```
 DAILY (7:00 PHT routine, headless)
   fetch → tolerance → run analysis → nutrition
   → gate re-check of today's session(s)
        cleared ─────────────► nothing to do
        blocked (hard) ──────► downgrade to the easy alternative, tell the athlete why
        consult ─────────────► report to the athlete, no change
   → notify the athlete (HRV verdict, session status, yesterday's run, EA flag, token reminder)
   → update notes + week plan → git push

 ON REQUEST (chat)
   decide (4-part rationale + PRINCIPLES IDs)
   → gate → cleared: upload | blocked: no | consult: data + pros/cons + research → the athlete decides
   → generator / session uploader → Garmin → watch

 WEEKLY (Sunday)        tracker + plan checks → plan the week, raise foreseeable consults
 MONTHLY (block)        roadmap review: verdicts, plateau playbook, phase criteria, library re-read
```

| Loop | Speed | Closed by |
|---|---|---|
| Train → Garmin → audit → next session | daily | The 7:00 routine (no longer depends on the athlete opening a chat). |
| HRV → intensity | daily | Gate (option B), enforced in code. |
| Load → volume | daily | Gate: higher of mechanical and TRIMP-load ACWR (cross-training now counts). |
| Recovery hours → hard sessions | per session | Gate: last hard **or long** run, not just the latest run. |
| Lift → sets → next targets | per session | `core_strength_progression.py`, used by the uploader. |
| Food → EA → Rule 12 | daily | Calories automatic; macros still manual. |
| Consult/override → outcome → gate tuning | months | `brain_decision_log.md`. |
| Progress → plateau → breakthrough | weekly/monthly | Tracker + playbook + roadmap review. |
| Session → notes → next session | per session | Coach writes the notes; Garmin data overrides notes when they disagree. |

## 4. Decisions behind the design (Oct 11, 2026)
- **One coach.** The Gemini coach was deleted (its useful rules moved into code); a separate
  lifting agent was rejected in favour of a progression script.
- **Gate verdicts:** BLOCK for clear-cut cases, CONSULT for nuanced ones (24–48 h after a
  hard/long run, heavy legs < 48 h after one, lifting on a low-HRV day), warnings otherwise.
- **HRV option B**, speed veto at **ACWR 1.5**, fail-closed for hard sessions on missing data,
  provisional verdicts for future dates.
- **Downgrade-only routine:** it may make a day easier, never harder, and never decides a consult.
- **Research:** digest (A) + code checks (C) + research log (D) + full library at block planning (B).
- **History:** generated ledger; "milestone" only when the ledger says so.

## 5. Still open
- **Zones:** the KB (Z2 162–174), the gate/plan checks (Garmin running zones: Z3 starts at
  176) and the archived operating manual (still cited by the run-analysis zone constants) disagree slightly; LTHR 191 vs 196.
- **ACWR evidence:** a 2025 cohort (RESEARCH_LOG.md) found single-run spikes predict injury
  and ACWR doesn't; the gate keeps ACWR (the athlete's choice) and the plan checks add the spike rule.
- **FBI** is not pace-corrected; a slower finish lowers it (warning only).
- **Macros** are manual until MyFitnessPal can be read; GitHub secrets hold an old
  MFP_EMAIL/MFP_PASSWORD attempt.
- **Token:** refresh-token lifetime unknown; renewed every 4 weeks.
- `sensor_audit_14d.py` overlaps the fetch script; `cloud_runner.py` and the Colab notebook
  are legacy; `scratch/` analysis scripts still use the old login.
- Treadmill runs make up most recent runs; the watch's treadmill distance and cadence are
  unreliable, so outdoor runs carry the cadence and form trends.
